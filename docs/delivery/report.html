人工智能文献知识图谱：课程交付报告

冻结日期：2026-10-11；提交截止：2026-10-13。V1 为正式系统，V2 为封存实验，禁止生产替换。不再采集训练数据、启动新训练或继续调参。

1. 领域与待解决的问题

选取人工智能学术文献领域。研究者需要找到与方法、任务相关的候选文献，核对作者、发表场所及原始来源，再判断是否引用。普通书目检索较难串联“作者—论文—方法—任务”的关联。本系统将 DBLP 书目与神经网络抽取的题名候选概念关联，用 Neo4j 提供可溯源检索和多跳探索。

系统用于缩小阅读范围、组织候选文献及查看证据，不自动认定论文支持某项结论，也不自动决定必引参考文献。没有可靠引用网络，不能提供真实被引次数。

2. 数据采集、清洗与图谱

原始书目来自 DBLP 官方公开 XML 快照，不将公开数据下载伪装成自行网页爬取。通过流式解析、AI 领域筛选、字段规范化、唯一键去重及引用一致性检查，形成 20,000 篇文献的结构化 CSV。数据摘要位于 kg_datasets/dblp/processed_ai/quality_summary.json，处理脚本保留在 scripts。

题名模型实际处理 19,999 篇，1 篇因超出固定长度拒绝，没有静默截断。形成 44,904 个实体提及、21,497 条候选断言；这些数量不是正确事实数量。V1 第 58 版包含 194,597 个节点、263,059 条关系。

实体层包括 Publication、Person、Venue、Concept、Mention、Assertion。书目关系包括 AUTHORED、PUBLISHED_IN；MENTIONS 和 DENOTES 将原文提及映射到概念；SUPPORTED_BY、HAS_HEAD、HAS_TAIL 保留候选关系及证据。USED_FOR、EVALUATED_ON 保存在 Assertion 的谓词属性中，未直接当作已认证科研事实连边。

作者采用 DBLP 主页身份辅助消歧，66,093 个作者身份匹配，9,062 个未决署名独立隔离。概念只采用 38 组受控别名，18 个模型版本概念保留。不能宣称作者完全消歧或概念全面归一。

2026-10-11 再次调用现有图谱导入器：图谱已存在，跳过重复导入，核对各类节点及关系数量一致，未重置数据库。实际收据：neo4j_import_verification.json。此项证明现有库与提交图谱包一致，不冒充已执行空库迁移验收。

3. 实体与关系抽取流程

采用 Pipeline：SciBERT + BIO 分类头识别 METHOD / TASK / DATASET，再使用带头尾实体标记的 SciBERT 关系分类器判断 USED_FOR / EVALUATED_ON / NO_RELATION。参考标注来自 AI 及原文复核，不是独立人工金标准。未决标签不强行转为负例。

V1 正式 NER 为第 08 轮开发记录中选定的第 4 轮检查点，RE 为第 15 轮开发记录中选定的第 3 轮检查点。训练、验证与历史测试记录封存，交付期间不重新使用旧测试调参。实际权重路径、大小、SHA-256 和生产标志见 models.json。

V2 输入完整摘要。训练使用冻结 Train65 的 941 个实体和 674 个已裁决实体对；未决项排除。按证据组每轮取样，251 组中 USED_FOR 196、EVALUATED_ON 29、NO_RELATION 26。随机种子为 20261011，NER 与 RE 均训练 6 轮，各按固定开发集规则选第 5 轮。NER 102 步、RE 378 步。开发集 Dev20 已暴露，test20 正文封存。

5. 有边界对照实验，不上线

V1 题名扩充实验在同一固定验证范围中，NER F1 从 75.14% 到 78.36%，Pipeline F1 从 66.47% 到 70.10%，但稀有类别护栏未通过，因此未替换生产。这些是开发分数，不与旧测试直接比提升。

V2 合法 BIO 解码将非法转移从 177 降为 0，NER F1 从 62.07% 到 62.87%，TASK F1 从 43.48% 到 44.80%。合法序列不保证实体语义或边界正确。一次 RE 类别加权将 NO_RELATION 召回从 2.08% 到 4.17%，仍仅正确拒绝 2/48，未解决主要问题。

6. 应用实现与演示

正式入口 http://127.0.0.1:8765/，启动 Start-Delivery.cmd。用户先启动 Neo4j Desktop 实例，再输入数据库密码；密码不写入文件、报告或压缩包。应用使用本机只读 HTTP 接口，中文词表展开、论文详情、作者身份、候选证据、局部图、作者 2 跳、方法 4 跳及 JSON/TXT 候选清单导出。

五篇 V1 演示书目和实际详情保存在 v1_demo_papers.json；实际冻结权重重新加载后进行五篇题名推理，见 v1_actual_inference.json。这不是准确率评测，也不声称五篇都是正确抽取。

摘要演示入口 /delivery-demo 使用三篇已存在的训练侧摘要：Codex、SQuAD、SuperGLUE，展示 AI 弱参考高亮、原文证据、离线关系示意图及人工审核勾选。没有新采集或新训练，也没有把 V2 摘要关系写入 V1。原文来源及限制保留，训练样例不可当作独立泛化证明。

AI 助手已阅读原文进行说明，但不能替用户完成真人签核。最终人工检查需用户打开演示页阅读三篇、勾选并导出 demo-human-review.json；未收到该文件前，状态保持 humanReviewed=false。SQuAD 冻结标签的已知漏标作为缺陷展示，不在交付冻结后悄悄修改标签。

实际浏览器截图、视频及交互收据保存于同目录。录屏展示本机真实应用操作，不是模拟页面；无配音版按演示操作文稿说明。

7. 验收、依赖与提交边界

Verify-Delivery.cmd 校验提交文件 SHA-256、正式 graphId、真实检索、三种非空图及错误请求拒绝。验收收据区分实际推理、图谱数量检查、HTTP 功能及浏览器操作，不将工程检查数量当作语义正确率。

提交 ZIP 包含源码、已处理书目、正式图谱、模型配置与 tokenizer、V1 两个生产权重、V2 原始 NER/RE 和加权 RE 共五份实际权重、Train65/Dev20 冻结数据、指标、报告和演示证据。逐成员重新读取校验 SHA-256。

不包含个人数据库、密码、虚拟环境、Neo4j 安装程序、完整 DBLP XML 及封存 test20 正文。新机器需 Python 3.12+、Neo4j（支持 HTTP Query v2），首次启动可安装已固定轻量依赖；模型推理另需 requirements-training.txt 的 Torch/Transformers。本机验证不等于离线裸机随包即用、所有 Neo4j 版本兼容或公网部署验收。

8. 已知限制与截止决策

P0：正式系统可启动、权重真实保存、图谱与文件一致、提交可验证；发现阻断即修复。P1：只修影响检索、展示、导出的缺陷。P2：长尾标签扩充、完整作者消歧、全量概念归一、摘要模型晋级、语义检索 Agent、全文证据和多用户部署均延后。

当前成果适合课程展示“采集清洗—深度学习抽取—Neo4j 入库—图谱检索应用”的闭环，不是高可靠科研事实库。精度及召回仍存在不足，无法保证教师评分。课程价值在于真实实现、可复现证据、正确评价及明确失败分析，而不是隐去低分或包装虚假的完整 F1。
