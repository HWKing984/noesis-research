# V2 测试执行证据与评测内容准入契约

本批仅解决独立审计P1-A/P1-B及抽样范围声明。旧包/生成器/测试保持原字节，只重放历史；不增加论文、不改现有标签、不训练或改V1。按ML数据准入规范，先封住工程证据门槛，不宣称模型正确率提高。

## 固定测试与受控执行

当前生产构建入口为`finalize_v2_admission.py`，不接收外部通过XML。它调用`run_v2_admission_checks.run()`，先验证冻结测试标识与源码SHA，收集测试集合，再实际运行pytest，检查退出码、实际case集合/去重、声明数量、错误/失败/跳过及运行元数据，保存日志、JUnit、Python/pytest版本、命令、起止时间、运行ID和源码SHA。执行前后源文件不得改变，拒绝覆盖已有执行目录。

冻结标识清单由实际pytest收集结果机械生成，覆盖旧205项与本批新测试；生成后再执行，不允许根据通过/失败结果删用例。完整清单随包交付。JUnit部分按[pytest官方输出说明](https://docs.pytest.org/en/stable/how-to/output.html)使用公开命令，不引入依赖。

shortcut: 本地执行收据是可重放证据，不是抵抗有权重写所有源码/清单/收据操作者的密码学证明；若需跨机构对抗性验收，升级到可信CI签名证明。记录里存在205个用例与证明执行过205个用例是两件事，不能只看XML标称总数。

## 两阶段评测准入

1. `prelock`：仅验证身份、组、曝光记录和跨拆分冲突，保存元数据/排除集/别名集SHA及受限抽样框；允许未知文本SHA，但状态为`pending_content_binding`且`evaluationAuthorized=false`。禁止注入正文。
2. `bind_content`与`finalize`：授权采集后把实际UTF-8全文摘要字节SHA绑定到不变的论文成员，再按此内容锁记录来源复核、近重复复核。最终检查必须有准确文本SHA、受根目录约束的非空内容、官方来源URL与同一论文身份、带审核人/时间/理由及真实文件SHA的两个复核记录；记录必须绑定该内容锁上下文。裸`passed=true`不够。空评测总体不能完成最终准入。

第二阶段将新文本SHA再次与历史排除集和其他拆分比对。预锁后修改身份/成员/历史上下文、改变原有已知SHA、缺少证据、错误来源、未锁抽样框或近重复未清除均阻断。记录通过只表示字节与审核档案一致；不是程序自动证明来源真实性或全量语义独立。后续仍须完整参考标注与独立的评价授权，当前函数不自动开启评测或训练。

当前12篇只在train，新验证/test/challenge成员仍0；本批未读取任何新/保留测试正文。正向内容绑定回归使用明确标识的合成文本与来源/审核元数据，只测试工程契约，不作为真实论文或标注成果。

## 抽样边界

只覆盖可规范识别的现代arXiv AI摘要候选，不推断覆盖全部DBLP。历史14,575条未映射书目仍保留原身份，不猜填来源。新总体、候选库存、选取种子、纳入概率与样本量尚未锁定，`samplingFrameLocked=false`；本批不抽样，不能宣称已完成代表性新评测。
