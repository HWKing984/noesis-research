RE 比类型多数基线的正关系 F1 仅高 **0.14 个百分点**，不能解释为强语义关系学习。52 个 EVALUATED_ON 参考正例均被识别，但同范围 15 个 DATASET 负例全部误报成 EVALUATED_ON。该类高召回很大程度与类型掩码和“合法对都判正”有关。

实际 Pipeline 共预测 1,239 条正边，其中 180 条精确匹配未决实体对，未计为已知错误。剩余严格可计分预测：132 TP、927 FP，另有 181 FN。927 FP 中 919 是非参考端点，8 是已知负例误报；181 个漏掉的参考正关系均有至少一个端点未被 NER 严格恢复。

这里的“非参考端点 FP”是相对于声明完整的 AI 实体参考的严格不匹配，不自动证明原文中对应的所有概念都不存在。AI 标签可能仍有范围或漏标问题。不能据此宣称系统真实世界错误率为 87.54%。

## 真实错误，下一步有明确顺序

1. **先处理 TASK 边界及类别的一致性与识别。** TASK 103 个参考中正确 50 个、漏匹配 53 个、额外预测 77 个。整个 NER 共有 44 个 FN 跨度与预测同类重叠、26 个 FN 与异类重叠、31 个 FN 无重叠；最佳轮记录 177 次非法 BIO 转移，严格解码没有把它们静默修成正确标签。例如 `iteratively refine only the intermediate layers` 被截成 `refine only the intermediate layers`；`time series learning` 被识别为 METHOD。这些边界/类别差异通过组合配对放大，优先级高于增加训练轮数。
2. **随后处理类型合法但文本不表达关系的负例。** 当前 RE 48 个负例中 47 个误报；正例高分只略超过类型多数基线。比如 `parameter sharing → fine-tune existing pre-trained models` 被预测成 USED_FOR；`query-key normalization → catch a sequence of tokens` 也被误报。未来如开展新实验，应从训练侧扩充与正例语境接近的已审负例，或单独比较负例训练策略；不能直接把 2,693 个未决训练对改成负例。
3. **EVALUATED_ON 需要正负例归属辨别，而不只是补正例。** 此次已有 57 个训练正例，单看 dev 正例召回 100% 会误导；15 个对应负例仍全部被判正。评测依据必须归属于正确模型，训练/预训练来源不能自动充当评测对象。

上述例子已出现在 dev，只用于解释本次结论，不能未经批准回流到训练集或用来反复调 dev。新的修复应使用训练侧对应错误模式，并明确新一轮实验是否授权；test20 在候选方案和最终测试计划确定前继续封存。
