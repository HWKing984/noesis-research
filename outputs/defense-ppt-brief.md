> 再让科研智能体站在它上面替你读文献 —— 每条结论都能点回原文的具体页码。

**三个关键词**：`弱监督知识抽取` · `可核验的科研 Agent` · `原文阅读闭环`

## P2 · 问题与目标

**科研文献的三层痛点**
1. **检索得到、读不到** —— 找到论文却拿不到全文，或摘要冒充全文
2. **答案不可核验** —— AI 的结论没有出处，或引用了却指不到原文哪一页
3. **信息割裂** —— 标题、摘要、实体关系、全文散落在不同工具里

**目标**：完成课程四个实验的同时，把这条链路做成**真能用的工作台**，而不是一次性演示脚本。

## P3 · 系统架构（四层）

```
┌─ 应用层 ────────────────────────────────────────────────┐
│  科研助手（主）· 论文库与图谱 · 原文阅读（PDF + 划词）      │
├─ 服务层 ────────────────────────────────────────────────┤
│  研究 API · 科研 Agent（SSE 流式）· 文档服务（全文抓取/缓存）│
├─ 契约层 ────────────────────────────────────────────────┤
│  统一证据契约 EvidenceRef · 文档可得性五态状态机           │
├─ 数据层 ────────────────────────────────────────────────┤
│  DBLP XML → AI 弱监督标注 → SciBERT NER/RE → Neo4j 图谱   │
└────────────────────────────────────────────────────────┘
```

**一页讲法**：底层是数据流水线；中间是**两条契约**（什么算证据、什么时候能读全文）；
上层是三个视图（问 / 找 / 读）。数据从不复制，只被引用。

**图谱构成**（第 31 轮）：Publication 20,000 · Person 75,155 · Venue 3,205 ·
Concept 29,878 · Mention 44,904 · Assertion 21,497

## P4 · 课程四实验对应

| 实验 | 要求 | 完成情况 |
|---|---|---|
| 实验一 | 采集 ≥1000 条数据 | 从 DBLP XML 按标题规则筛出 **20,000 篇**（2015–2025 AI 相关） |
| 实验二 | 实体抽取模型 | SciBERT token 分类，**7 个 BIO 标签**（METHOD / TASK / DATASET） |
| 实验三 | 关系抽取模型 | SciBERT + 头尾实体标记：**USED_FOR / EVALUATED_ON** |
| 实验四 | 入库 + 可用应用 | Neo4j 幂等导入（19.5 万节点 / 26.3 万关系）+ 只读检索应用 + 科研 Agent 工作台 |

**标注路线（必讲）**：AI 伪标签（`ai_pseudo`）**弱监督**，不要求人工标注 ——
AI 只承担标注工具，训练与评测仍是 SciBERT 深度模型，划分按**论文组隔离**（训练 1,600 / 验证 200 / 测试 200）。

## P5 · 技术亮点（挑 4 条重点讲）

**① 引用可核验：三级分离，不是一个布尔**
- 来源类型（图谱书目 / 候选断言 / 全文段落 / 外部记录）
- 证据深度（题名 / 摘要 / **全文**）
- 核验等级（未核验 → ID 有效 → 证据支持 → 语义核对）
> **「引用了一篇真实存在的论文」≠「这段话被论文支持」**，系统分得开，界面上也分开显示。

**② 全文可得性 = 五态状态机，如实呈现**
`可读 / 仅出版社页 / 未收录全文 / 获取失败 / 需上传`
- 「未收录」（事实，不再重试）与「获取失败」（本次失败，可重试）**永不混同**
- 没拿到全文**绝不给阅读入口** —— 不把摘要伪装成全文

**③ 真抓取 + 安全加固（不制造假成功）**
来源优先级 arXiv → OpenAlex → Semantic Scholar → 用户上传；
域名白名单 + 重定向逐跳复查 + 显式禁用环境代理 + `%PDF-` 魔数 + 大小上限 + **SHA-256 落库**。
> 实测：真下载 arXiv 论文 2.2 MB、真抓取 6.8 MB 全通过；白名单外域名被拒。

**④ 引用可跳页：quote 定锚，解析器换了也不指错**
回答中的引用 → 打开原文 → 跳到第 4 页 → 高亮对应段落。
定位同时存偏移量与**原文快照（quote）**；重锚定失败就如实显示「锚点丢失」，**绝不猜位置**。

**⑤ 作者身份消歧不模糊合并**（可选加页）
79,698 个署名匹配到 66,091 个 DBLP 作者身份，9,064 个**未决署名单独保留**、
绝不按相似度强行合并 —— 宁可少归一，不制造错误身份。

## P6 · 成果数据（如实口径，逐条带限定语）

**数据与图谱**
- 20,000 篇文献 / 194,639 节点 / 263,059 关系 / **21,497 候选断言**
- 候选断言全程以 `candidate` 呈现，**从不当作已核实事实**

**模型指标（同 dev 口径，与 AI 参考标签的一致性）**
| 指标 | 最新 | 限定语 |
|---|---|---|
| 摘要 NER 总体 F1 | **72.02%**（第 48 轮，46 轮为 70.84%） | 同一 dev 16 篇；**未晋级** |
| 摘要关系（条件正关系）F1 | **94.18%**（第 46 轮，42 轮 92.06%） | **不能替代完整流程**指标 |
| 完整关系开发对照 F1 | 冻结 42 轮 **54.35%**；46 轮 39.53%、48 轮 39.84% | 同 dev 7/19 篇 |

> **口径必须照着念**：以上衡量的是**与 AI 参考标签的一致性，不是人工金标准上的正确率**；
> Precision / Recall / F1 / 覆盖度分别披露，未校准的 softmax 分数**不是事实概率**。

**工程纪律：多轮实验主动「拒绝晋级」**
当新训练让完整 pipeline 变差（54.35% → 39.53%）或错报增加时，**拒绝替换生产图** ——
生产图谱始终是第 31 轮版本（与旧图按 `graphId` 隔离共存）。
> 一句话：**指标不好看就不上线**，每轮的拒绝记录、失败凭据与来源链全部留档。

**工程质量**
- 数据侧回归：**378 项通过**（第 50 轮，隔离临时目录，零失败/错误/skip）
- 科研工作台：Python **138 项**（适配器 44 · 契约 58 · API 37）+ Agent 套件 176 项 + 前端单测 19 项
- **真实浏览器端到端断言 47/47 全过**（真 Neo4j + 真大模型）
- Agent 实测：**6 步自主工具调用**、回答 3,903 字、引用核查 **48/53 通过**、按句可溯率 **69%**

## P7 · 现场演示路径（建议 3 分钟）

1. **只读检索应用**（8765）：搜 `transformer` → 点结果里的证据按钮 → 看「这条证据能证明什么、不能证明什么」
2. **科研助手**（4173）：提问「Transformer 之后有哪些注意力机制的改进工作？」
   → **看着它检索**（工具步骤实时出现）→ 回答下方是**引用核查结论卡**
3. **点引用** → 证据抽屉 → 论文详情 → 点「阅读全文」
4. **阅读器**：选中 §3.2.1 段落 → 「解释」→ 右侧生成带页码的证据卡 → 点页码锚**跳回原文高亮**

> 若 Neo4j 未启动，第 1–3 步会显式报「图谱不可用（503）」而**不是空结果** —— 这本身就是设计的一部分。

## P8 · 难点与解决（答辩加分项）

| 难点 | 解决 |
|---|---|
| 弱监督标注质量不稳定，容易越调越差 | 建立「对比 — 拒绝晋级」流程：每轮与冻结基线同 dev 对照，劣化即拒绝并留档 |
| 上游开源组件栈不兼容（Next 16 / React 19 vs 本项目 Vite + React 18） | 只移植交互与数据契约、不搬代码；参考仓库以只读台账管理 |
| pdf.js 在 pnpm 严格隔离下 worker 解析失败 | 将 `pdfjs-dist` 提为直接依赖并锁版本，worker 路径固化 |
| 「重复抓取已缓存论文」撞状态机终态导致 500 | 抓取接口改**幂等**：已有缓存直接返回、不重复下载（真实验证时发现并修复） |
| AI 回答可能编造引用 | 回答落库前过**引用核查闸门**：统计实际引用数与按句可溯率，不达标即判失败 |

## P9 · 已知边界与后续（如实说，不回避）

**当前边界**
- 模型指标为 **AI 参考标签口径**；完整 EVAL 支持为 0，高可靠模型仍在多轮实验中，**未替换生产图**
- 关系为**候选断言**，不做「是否必须引用」判定（本版 DBLP 数据不含引文 CITES）
- 阅读记录与证据卡目前为会话内，跨会话持久化未完成

**后续路线**
- P2：全文问答（PaperQA2 全文索引）+ 证据卡与阅读记录持久化
- P3：公式截图解释（视觉模型）、批注
- P4：阅读内容与图谱断言联动、自动研究笔记

## 可能的评委提问（准备好答案）

**Q1：你的 F1 是人工标注的吗？**
> 不是。这是**与 AI 参考标签的一致性**，README 首页和 PPT 都醒目标注了口径。
> 弱监督路线的价值是「零人工标注跑通完整流水线」；真实正确率需要人工金标准，目前不具备，我们不冒充。

**Q2：AI 标注算不算「自己标自己」？**
> AI 是**标注工具**，标注结果经同会话复核、按论文组隔离划分，并保留来源链；
> 模型是 SciBERT 在标注数据上训练，评测在**冻结的 dev/test** 上做，测试集内容未被消费。

**Q3：为什么最新指标反而比旧轮次低，还敢拿出来讲？**
> 因为**口径变了、范围更严格**，而且我们建立了「劣化即拒绝晋级」的纪律 ——
> 旧的 54.35% 与后来的 39.53% 是不同范围/不同对照下的数字，我们不做跨范围美化。
> **生产图始终是验证过的那一版**，这正是工程可信度的证明。

**Q4：候选断言是什么，为什么都标 candidate？**
> 弱监督抽取难免误报，所以这些关系**永远保持候选**、不提升为事实；
> 界面上与书目事实分区呈现，每条置信度与证据可展开核查。

**Q5：为什么不做引用网络 / 被引次数？**
> 本版 DBLP 数据不含 CITES 关系（官方说明），硬做就是编造。宁可明说「不做」。

**Q6：系统最核心的创新点是什么？**
> **把「可核验」做成工程契约** —— 证据三级分离、全文五态状态机、引用带 quote 定锚。
> 多数同类系统止步于「AI 给个答案」，我们让每个结论都能点回原文的具体位置。
